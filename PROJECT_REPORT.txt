1. EXECUTIVE SUMMARY & ABSTRACT
----------------------------------------------------------------------------------------------------
Traditional software development linters and static analyzers typically rely on regex-based keyword
matching. This results in high rates of false positives and a complete inability to reason about
program syntax, scoped data flows, and runtime control execution paths. Conversely, traditional
optimizing compilers focus purely on execution speed and binary footprint reduction without verifying
security invariants or remediating vulnerabilities.

SecureCompilerAI bridges this architectural divide by introducing a unified semantic compiler
pipeline that integrates:
  1. Multi-language source code parsing (Python, C, Java)
  2. Scoped symbol resolution and lexical scope hierarchies
  3. Intermediate Representation (Three-Address Code Quadruples)
  4. Control Flow Graph (CFG) basic block partitioning
  5. Abstract Syntax Tree (AST) semantic taint and security rule verification
  6. Automated, verified secure code transformations
  7. Explainable compiler optimization passes (Constant Folding, Dead Code Elimination)
  8. Three-stage semantic verification gates (Syntax, Symbol Preservation, Regression Safety)
  9. Automated execution of 31 predefined multi-language benchmark test cases
 10. Persistent SQLite database storage and multi-format reporting (PDF, HTML, JSON)

3. THE 11-STAGE COMPILER PIPELINE
====================================================================================================
Stage 1:  Source Code Input
          Accepts Python (.py), C (.c, .h), and Java (.java) code via editor or file upload.

Stage 2:  Lexical Analysis
          Generates token stream classifying keywords, identifiers, operators, literals, comments.

Stage 3:  Syntax Analysis
          Grammar validation, line/column tracking, and syntax error diagnosis.

Stage 4:  Abstract Syntax Tree (AST) Generation
          Hierarchical tree normalization with node IDs, labels, line numbers, and child relations.

Stage 5:  Semantic Analysis
          Lexical scope resolution, symbol table creation, undefined and unused variable tracking.

Stage 6:  Intermediate Representation (IR)
          Generates Three-Address Code (TAC) Quadruples (opcodes, arguments, result temporaries).

Stage 7:  Control Flow Graph (CFG)
          Leader identification, basic block partitioning, and directed edge branch linking.

Stage 8:  Security Vulnerability Detection
          Non-regex semantic inspection across 5 major CWE categories.

Stage 9:  Semantic Verification
          Pre- and post-transformation checks ensuring syntax validity and symbol preservation.

Stage 10: Code Hardening & Optimization
          Automated secure code rewrites, constant folding, and dead code elimination.

Stage 11: Final Output & Audit Certification
          Side-by-side Monaco diff, 31 benchmark suite execution, and PDF/HTML audit reports.

4. MODULE SPECIFICATIONS & IMPLEMENTATION DETAILS
====================================================================================================

MODULE 1: INTELLIGENT SOURCE CODE ANALYSIS & SECURE PARSING
----------------------------------------------------------------------------------------------------
- Lexical Analyzer (app/compiler/lexer.py):
  Tokenizes input into 5 distinct categories: Keywords, Identifiers, Operators, Literals, Delimiters.
  Calculates token counts and classification breakdowns.

- Multi-Language Parsers (app/compiler/parser.py, app/compiler/ast_analyzer.py):
  * Python: Uses ast.parse to capture AST nodes and exact syntax error coordinates.
  * C: Uses pycparser with injected typedefs (size_t, FILE, uint32_t) and resilient C AST generator.
  * Java: Uses javalang.parse.parse with wrapper fallbacks for classless snippets.
  * AST Analyzer: Standardizes raw language trees into interactive visual node schemas.

- Scoped Symbol Table & Semantic Analyzer (app/compiler/symbol_table.py, semantic_analyzer.py):
  * Scoping: Maintains lexical scope hierarchy (global -> function -> block -> class).
  * Undefined Variable Detection: Flags symbols referenced in expressions without prior declaration.
  * Unused Variable Detection: Flags local identifiers declared/assigned but never read.
  * Unreachable Code Detection: Identifies dead statements trailing return, raise, throw, break, exit.
  * Type Mismatch Warnings: Detects incompatible operations between disparate literal types.

- Intermediate Representation & CFG (app/compiler/intermediate_representation.py, control_flow.py):
  * Three-Address Code (TAC): Converts high-level constructs into linearized quadruples.
    Opcodes: ASSIGN, BINOP_ADD, BINOP_SUB, CMP_EQ, JUMP, JUMP_IF_FALSE, LABEL, CALL, PARAM, RETURN.
  * Basic Block Partitioner: Groups TAC instructions by leader rules into basic blocks with
    predecessors, successors, and directed jump/fallthrough edges.


MODULE 2: SEMANTIC SECURITY VERIFICATION ENGINE
----------------------------------------------------------------------------------------------------
Inspects AST call nodes, statement parameters, string concatenations, and control flow paths.

Implemented Vulnerability Categories & CWE Rules:
1. SQL Injection (CWE-89) - Critical:
   Detects dynamic string concatenation, f-strings, and sprintf formatting in SQL execution sinks
   (cursor.execute, Statement.executeQuery, sqlite3_exec).

2. OS Command Injection (CWE-78) & Code Injection (CWE-94/95) - Critical:
   Flags os.system, subprocess with shell=True, system(), Runtime.getRuntime().exec(), eval(), exec().

3. Memory Safety Flaws (CWE-120, CWE-134, CWE-416) - Critical / High:
   Detects classic buffer overflows (gets, unbounded strcpy/strcat/sprintf), format string vulnerabilities
   (printf without format specifiers), and use-after-free pointer dereferences after free(ptr).

4. Deserialization of Untrusted Data (CWE-502) - Critical:
   Identifies pickle.loads(), yaml.load() without SafeLoader, and ObjectInputStream.readObject().

5. Authentication & Cryptography (CWE-798, CWE-328, CWE-330) - High / Medium:
   Detects hardcoded secrets/passwords, weak hash algorithms (MD5, SHA-1), and predictable random
   generators (random.random, rand, new Random) used in security token contexts.

6. General Security Issues (CWE-22, CWE-377, CWE-732, CWE-391) - High / Medium / Low:
   Detects path traversal (open with user input), insecure temporary files (tempfile.mktemp), overly
   permissive permissions (chmod 0777), and silent exception suppression (except: pass, empty catch).

Security Scoring Formula:
   Score = max(0.0, 100.0 - (25 * Critical + 15 * High + 8 * Medium + 3 * Low))


MODULE 3: VERIFIED SECURE CODE TRANSFORMATION & EXPLAINABLE OPTIMIZATION
----------------------------------------------------------------------------------------------------
- Automated Secure Hardening (app/optimizer/secure_transformations.py):
  * SQL Injection: Rewrites dynamic queries to parameterized queries with bound tuples:
    cursor.execute(f"SELECT * FROM users WHERE id = '{uid}'")
    -> cursor.execute("SELECT * FROM users WHERE id = ?", (uid,))
  * Command Injection: Converts shell strings to safe argument arrays with shell=False:
    os.system("ping " + host) -> subprocess.run(shlex.split("ping " + host), shell=False, check=True)
  * Hardcoded Secrets: Replaces cleartext credentials with environment variable lookups:
    API_KEY = "sk_live_123" -> API_KEY = os.getenv("API_KEY") (auto-injects import os)
  * Weak Hashing: Migrates MD5/SHA-1 to SHA-256 or Argon2id/bcrypt.
  * C Buffer Safety: Replaces gets() with fgets(), and strcpy() with bounded strncpy + null-terminator.
  * Insecure Temp Files: Replaces mktemp() with atomic NamedTemporaryFile().
  * Deserialization: Replaces pickle.loads() with safe json.loads().

- Compiler Optimization Passes:
  * Constant Folding: Evaluates static constant expressions at compile-time (e.g. 24*60*60 -> 86400).
  * Dead Code Elimination (DCE): Prunes unreachable statements after returns and dead branches.

- Three-Stage Semantic Verification Gate (app/verification/regression_verifier.py):
  * Gate 1 (Syntax Check): Verifies transformed code re-parses with 0 syntax errors.
  * Gate 2 (Symbol Preservation): Verifies all original functions, classes, and variables remain intact.
  * Gate 3 (Regression Safety): Verifies security score improved and no secondary flaws were created.

7. test_cases:
   - id (Integer, Primary Key)

6. REST API ENDPOINTS SPECIFICATION
====================================================================================================
- POST   /api/analyze              Runs lexical, syntax, AST, semantic, IR, CFG analysis.
- POST   /api/security/scan        Executes CWE security rule engine and computes security score.
- POST   /api/transform            Applies automated secure code transformations and computes diffs.
- POST   /api/verify               Runs 3-stage semantic verification gatekeeper.

- POST   /api/tests/run            Executes an individual test benchmark by ID.
- POST   /api/tests/run-all        Executes all test benchmarks with optional filters.
- GET    /api/history              Lists historical analysis records.
- GET    /api/history/{id}         Retrieves full stored compilation telemetry for a specific run.
- DELETE /api/history/{id}         Deletes an analysis record.
- GET    /api/samples              Lists educational vulnerable and clean sample programs.
- GET    /api/reports/download/{id} Exports audit reports in PDF, HTML, or JSON format.
